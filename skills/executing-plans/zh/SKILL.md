# 执行计划

## 概述

加载计划，进行严格审查，执行所有任务，完成后提交报告。

**开始时声明：** “我正在使用‘执行计划’技能来实施该计划。”

**注意：** 请告知您的人类合作伙伴，Superpowers 在能够访问子代理的情况下效果会好得多。如果在支持子代理的平台上运行，其工作质量将显著提高（Claude Code、Codex CLI、Codex App 和 Copilot CLI 均符合条件；请参阅 `../using-superpowers/references/` 中各平台的工具参考）。 如果可用子代理，请使用 superpowers:subagent-driven-development 技能，而非本技能。

## 流程

### 步骤 1：加载并审查计划
1. 读取计划文件
2. 进行批判性审查——识别计划中存在的任何疑问或顾虑
3. 若有疑虑：在开始前向人类合作伙伴提出
4. 若无疑虑：为计划项创建待办事项并继续执行

### 步骤 2：执行任务

对于每个任务：
1. 标记为 in_progress
2. 严格遵循每个步骤（计划包含简明易行的步骤）
3. 按规定执行验证
4. 标记为“已完成”

### 步骤 3：完成开发

所有任务完成并验证后：
- 宣布：“我正在使用‘完成开发分支’技能来完成这项工作。”
- **必备子技能：** 使用超能力：finishing-a-development-branch
- 遵循该技能进行测试验证、呈现选项并执行选择

## 何时应暂停并寻求帮助

**出现以下情况时请立即停止执行：**
- 遇到阻塞问题（缺少依赖项、测试失败、说明不明确）
- 计划存在严重漏洞，导致无法开始
- 你不理解某项说明
- 验证反复失败

**请寻求澄清，而不是凭空猜测。**

## 何时需要回顾先前步骤

**在以下情况下返回“审查”（步骤 1）：**
- 合作伙伴根据您的反馈更新了计划
- 基本方法需要重新考虑

**不要强行突破阻碍**——暂停并寻求帮助。

## 请记住
- 首先对计划进行批判性审查
- 严格遵循计划步骤
- 不要跳过验证步骤
- 计划要求时请参考相关技能
- 遇到阻碍时暂停，不要凭空猜测
- 未经用户明确同意，切勿在 main/master 分支上开始实现

## 集成

**必需的工作流技能：**
- **superpowers:using-git-worktrees** - 确保工作区隔离（创建新工作区或验证现有工作区）
- **超级技能：编写计划** - 创建本技能执行的计划
- **超级技能：完成开发分支** - 在所有任务完成后结束开发
