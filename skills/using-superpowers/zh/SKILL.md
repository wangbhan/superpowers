## 规则

**在做出任何回应或采取任何行动之前，先调用相关或被要求的技能**——包括提出澄清问题、探索代码库或检查文件。 如果发现该技能不适用于当前情况，你不必使用它。

**进入计划模式之前：**如果你尚未进行头脑风暴，请先调用“头脑风暴”技能。

然后宣布“使用[技能]来[目的]”，并严格遵循该技能的指引。 如果该技能包含检查清单，请针对每个项目创建一个待办事项。

## 技能优先级

当多个技能适用时，流程类技能优先——它们确定解决思路，随后由实现类技能（如前端设计等）付诸实施。 头脑风暴和系统性调试是《超能力》中最常见的流程技能，但这一规则适用于所有技能。

- “让我们构建 X” → 先使用《超能力》：头脑风暴，再使用实施技能。
- “修复这个 bug” → Superpowers：先进行系统性调试，再运用领域技能。

## 危险信号

以下想法意味着“停止”——你正在为自己找借口：

| 想法 | 现实 |
|---------|---------|
| “这只是个简单的问题” | 问题即任务。先检查技能。 |
| “我需要先了解更多背景” | 技能检查应在澄清问题之前进行。 |
| “让我先探索一下代码库” | 技能告诉你“如何”探索。先检查技能。 |
| “我可以快速查看 git/文件” | 文件缺乏对话背景。先检查技能。 |
| “让我先收集信息” | 技能会告诉你“如何”收集信息。 |
| “这不需要正式的技能” | 如果存在相关技能，就使用它。 |
| “我记得这个技能” | 技能在不断演进。请查阅最新版本。 |
| “这不算一项任务” | 行动即任务。先确认是否存在相关技能。 |
| “这个技能太复杂了” | 简单的事情往往变得复杂。还是用它吧。 |
| “我先做这一件事就好” | 采取任何行动之前请先确认。 |
| “这感觉很有成效” | 缺乏纪律性的行动会浪费时间。技能可防止这种情况。 |
| “我知道那是什么意思” | 了解概念 ≠ 运用技能。请调用该技能。 |
